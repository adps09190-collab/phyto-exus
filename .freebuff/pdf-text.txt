1. Website Overview & Demo Constraints
Demo Mode Constraint: For the ideathon presentation, this website will operate in an isolated prototype state.
External hardware connections (ESP32/Wi-Fi) are decoupled. All live dashboard data, charts, and events must
be driven by a local JavaScript simulation script (mocking telemetry over time). The UI must behave exactly as
if it were receiving real-time JSON payloads from the physical botanical extraction setup.
The platform serves as a uniﬁed digital hub for small-scale botanical extraction R&D. Its primary frontend goal
is to translate raw hardware sensor readings into structured, traceable research records while clearly surfacing
safety states.
2. Implemented Telemetry Parameters
To maintain strict alignment with the existing prototype BOM, the frontend data schema must only expect and
process the following speciﬁc variables. Do not build UI components for sensors that do not exist in the current
reference stack.
Variable Name Hardware Data Type UI Role in Botanical R&D
temperature_c DHT22 Float (°C) Primary process variable. Plotted on main timeline. High
values trigger Warning/Alert states for solvent safety.
humidity_rh DHT22 Float (%) Ambient/chamber conditions. Used as secondary
metadata in experiment records to ensure environmental
reproducibility.
vapor_signal MQ-3 Integer (Raw) Alcohol-vapor proxy signal. Treated as a hazard indicator
for extraction leaks, not a calibrated PPM concentration.
heater_state 5V Relay Boolean (0/1) Electrical load status. Displayed as a binary ON/OFF
indicator. Automatically forced to 0 during Alert/Fault
conditions.

3. System States & UI Color Coding
The website must visually communicate the safety state of the extraction process at all times. Use the
following color-coded UI schema across badges, borders, and notiﬁcation banners based on the mocked
system_state variable.
NORMAL (Green / #10b981)
All variables (temp, vapor) within safe operating envelope. System monitoring and logging actively. Heater allowed to
operate.
WARNING (Yellow / #eab308)
Approaching threshold limit (e.g., rising vapor proxy). UI triggers soft notiﬁcation. Operation continues but is ﬂagged
in timeline.
ALERT (Orange / #f97316)
Critical limit exceeded. The UI must show heater_state forced to OFF. Requires manual simulated
acknowledgement to clear.
FAULT (Red / #ef4444)
Simulated hardware failure (e.g., DHT22 disconnected). Missing/implausible data. UI obscures live values with a
"Data Invalid" overlay.
LOCK (Purple / #7c3aed)
Repeated critical faults. System disabled. UI displays a full-screen or modal block requiring a deliberate "Reset
Protocol" interaction.
